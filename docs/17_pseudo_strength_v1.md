# 17. pseudo_strength_v1：程序化口型强度先验（方法详解）

> 代码位置：`articulm_dataset_factory/articulm_corpus/linguistic/articulation.py`
> （函数 `pseudo_strength(token, prev_token, next_token) -> float`）
> 版本标识：契约中 `strength_source: "pseudo_strength_v1"`，规则版本常量
> `STRENGTH_RULE_VERSION = "pseudo_strength_v1"`
> 本文撰写日期：2026-08-22（与代码逐行核对）

## 1. 定位与设计动机

### 1.1 它要解决的问题

teacher 接口（`https://tapi.anispark.xyz/tdoge-core/api/tts/visemes`）返回的
`mouthValue`（契约里存档为 `raw_value`）存在两个致命缺陷：

1. **中文语音的 mouthValue 是 100/0 二值**（有口型/无口型），无中间强度
2. **中文语音处理英文文本时 mouthValue 为 null**，完全不产出口型强度

而模型需要的是 0-100 的**连续**强度回归目标。若直接用接口原值：
英文失去 strength 监督、标签退化为与 viseme_id 冗余的二值指示、
strength 头退化为"静音检测器"（详见 docs/16 相关讨论）。

### 1.2 核心假设

**strength ≈ 该音素的发音努力度 / 口型开合程度**，而这两者可以从 token 自带的
articulatory（发音特征）字段近似推出。因此 pseudo_strength_v1 是一套
**分层加法 + 乘法调制的规则模型**，不依赖接口强度值，只用语音学特征。

### 1.3 它是先验，不是真值

- 契约明确 `strength` 为"程序化先验"，`strength_source` 单独标识，
  永远不得标为 Human Gold（CLAUDE.md 硬规则）
- 预训练阶段 loss 权重 0.3（低于 Human Gold 阶段的 1.0）
- Human Gold 微调阶段 source_weight 降为 0（config/train_v1_50m_human_gold.yaml），
  由人工标注接棒

## 2. 计算规则（与代码一一对应）

输入是一个 token 的完整特征（phoneme、articulatory、surface_tone、stress、
syllable_role、边界标记），以及左右相邻 token（仅协同发音项使用）。

### 2.1 第 0 层：静音（短路返回）

```python
if articulatory.type == "silence":
    return 0.0
```

停顿/休止位置定义上无发音努力。

### 2.2 第 1 层：按音素类型给基线（加法）

**元音**（按舌位高度，开口度越大越强）：

| articulatory.height | 基线 |
|---|---|
| low | 88.0 |
| mid | 78.0 |
| high | 68.0 |
| 其他/未知 | 72.0 |

圆唇（`rounded=true`）**+4**（唇部额外用力）。

**辅音**（按发音方式）：

| articulatory.manner | 基线 |
|---|---|
| stop（塞音） | 74.0 |
| affricate（塞擦音） | 70.0 |
| nasal（鼻音） | 62.0 |
| fricative（擦音） | 60.0 |
| lateral（边音） | 56.0 |
| approximant（近音） | 50.0 |
| 其他 | 58.0 |

发音部位修正：**双唇音（bilabial）+14**、唇齿音（labiodental）+6
（嘴唇参与的辅音在视觉上最明显）。未知类型兜底 55.0。

### 2.3 第 2 层：韵律调制（加法 + 乘法）

**音节角色**（加法）：

| syllable_role | 修正 |
|---|---|
| nucleus（韵核） | +5 |
| coda（韵尾） | -4 |
| onset / other | 0 |

**中文声调**（乘法，`surface_tone`）：

| tone | 系数 | 依据 |
|---|---|---|
| 1（阴平） | ×1.00 | 平调基准 |
| 2（阳平） | ×1.02 | 上升略用力 |
| 3（上声） | ×0.96 | 低沉压低 |
| 4（去声） | ×1.04 | 下降最用力 |
| 5（轻声/静音调） | ×0.86 | 弱读 |

**英文重音**（乘法，`stress`）：

| stress | 系数 |
|---|---|
| 1（主重音） | ×1.06 |
| 2（次重音） | ×1.03 |
| 0（非重读） | ×0.92 |

### 2.4 第 3 层：边界效应（加法 + 乘法）

| 条件 | 修正 | 语音学依据 |
|---|---|---|
| `word_start` | +1.5 | 词首起势用力 |
| `word_end` | -1.0 | 词尾收敛 |
| `phrase_end` | ×0.92 | 语尾衰减（declination） |

### 2.5 第 4 层：协同发音（唯一使用上下文的项）

| 条件 | 修正 | 依据 |
|---|---|---|
| 元音 且 前一个 token 是双唇音 | +2 | 唇形残留 |
| 辅音 且 前后都是元音 | +2 | 元音间过渡更饱满 |
| 近音（approximant） | -3 | 本身就弱 |

### 2.6 计算顺序（重要）

各层的应用顺序固定为：

```text
基线(第1层) -> 音节角色± -> 声调× -> 重音× -> 词首/词尾± -> 短语尾× -> 协同发音± -> clamp/round
```

顺序影响结果：协同发音的 ±2 在所有乘法**之后**累加（不会被重音系数稀释）。

一个容易忽略的行为：**中文 token 的 stress 恒为 0（契约规定），因此中文
所有音素都吃 ×0.92（非重读系数）**，相当于隐式的"中文整体系数"，实际效果
是把中文基线整体压低 8%。见 §3 示例的逐项复算。

### 2.7 收尾

```python
return round(max(0.0, min(100.0, s)), 1)   # clamp 到 [0,100]，保留一位小数
```

## 3. 计算示例（实际调用函数验证过的数值）

以下数值全部实际调用 `pseudo_strength()` 验证；中文示例按契约
stress=0，因此都含 ×0.92（见 §2.6 的顺序说明）。

| 场景 | 音素 | 计算路径（按 §2.6 顺序） | 结果 |
|---|---|---|---|
| 中文 ā 韵核 | a | (88+5) ×tone1(1.00) ×stress0(0.92) = 85.56 | **85.6** |
| 中文 à 韵核（去声） | a | 93 ×1.04 ×0.92 = 88.98 | **89.0** |
| 中文 ǎ 韵核（上声） | a | 93 ×0.96 ×0.92 = 82.06 | **82.1** |
| 中文 i 轻声调 | i | (68+5) ×0.86 ×0.92 = 57.79 | **57.8** |
| 英文主重读 s 音节首 b | b | (74+14) ×1.06 = 93.28（未设词首标记） | **93.3** |
| 英文非重读 s | s | 60 ×0.92 = 55.2 | **55.2** |
| 中文韵尾 m | m | (62+14-4) ×1.00 ×0.92 = 66.24 | **66.2** |
| ba 中的 a（双唇后元音） | a | 93 ×0.92 + 2 = 87.56（±2 在乘法后） | **87.6** |
| 元音间的 s | s | 60 ×0.92 + 2 = 57.2 | **57.2** |
| 短语尾的 ā | a | 93 ×0.92 ×0.92 = 78.71 | **78.7** |
| 静音 `_` | - | 短路返回 | **0.0** |

## 4. 产出分布（训练集实测，data_report.json）

| 统计量 | 值 |
|---|---|
| 均值 / 标准差 | 66.6 / 19.0 |
| p05 / p50 / p95 | 41.2 / 69.0 / 89.5 |
| 取值数 | 连续（一位小数，2000 句抽样 391 种不同值） |

分类别均值符合物理直觉：元音类 67-70、擦音类 ~80、闭唇/静音类接近 0。
模型在该先验上训练后，测试集 strength MAE 0.34（0-100 量纲）。

## 5. 与接口 mouthValue 的对比

| 维度 | mouthValue（raw_value） | pseudo_strength_v1 |
|---|---|---|
| 值域 | {0, 100}（中文）/ null（英文） | 连续 0-100 |
| 英文覆盖 | 无 | 完整（同一套规则跨语言） |
| 类内区分度 | 无 | 韵律/边界/上下文调制 |
| 与 viseme_id 信息冗余 | 几乎完全冗余 | 互补 |
| 可解释性 | 黑盒 | 每一项可归因 |

契约处理：`raw_value` 仅作为 teacher metadata 存档（不进编码器，也不作标签）；
`strength` 一律由本规则生成，`strength_source` 标注来源。

## 6. 已知局限（转入 Human Gold 阶段的原因）

1. **系数是拍定的先验**，非数据拟合：各修正项（+14 双唇、×1.04 去声等）
   来自语音学常识的量级估计，未经真实口型运动捕捉校验
2. **无时长概念**：同一音素在快语速/慢语速下强度应不同，规则无从感知
   （与 V1 模型不输入 duration 的限制同源）
3. **个体差异缺失**：说话风格、情感状态不可见
4. **与 viseme 的耦合是间接的**：strength 只看音素特征，不参考 viseme_id，
   两者的联合分布（同一 viseme 类内强度如何随语境变化）只有一阶近似

这些正是 Human Gold 标注要修正的对象：微调阶段模型学到的
"真实标注 - 程序化先验"残差，本质上就是对上述局限的修正。

## 7. v2 变体（2026-08-22 新增，已投产一版语料）

针对 §2.6 记录的"中文 ×0.92 整体系数"问题，工厂新增 `pseudo_strength_v2`：

- **语义**：重音乘子只作用于英文 token；中文 `stress=0` 是契约占位而非
  "非重读"，不再乘 0.92。英文数值与 v1 逐 token 一致，静音行为不变
- **实现**：`pseudo_strength(..., rule="pseudo_strength_v2")`；relabel-build
  新增 `--strength-rule` 参数；样本落盘时 `strength_source`/`strength_rule`
  如实记录所 用规则版本
- **v2 语料**（`config/data_v1_strength_v2.yaml`）：
  - `data/corpus_strength_v2.jsonl`（140k 句）
  - `data/v2/{train,validation,test}.jsonl`：与 v1 切分**句级完全一致**
    （同 seed 同参数，126,000/6,009,118 tokens 一字不差），仅 strength 值不同
    --控制变量实验可用
  - 分布变化（test 集）：中文 mean 64.84 -> 70.41（+8.6%），上限 92.5 -> 100；
    英文 mean 72.57 不变。中文/英文强度分布由此更可比（70.41 vs 72.57）
- v1 语料与 `archive/baseline_v1_20260821_synthetic` 基线不受影响

## 8. 变更约束

- 修改规则**必须**升版本号（如 `pseudo_strength_v2`），不得原地改语义：
  已发布的语料带版本标识，原地改动会造成同名字段两种含义
- 新版本需同步更新：契约文档、`STRENGTH_RULE_VERSION`、
  TRAINING_DATA.md、以及模型的 source_weights 配置
- 模型侧永远不把 `strength` 值当输入（CLAUDE.md 硬规则）
